# 256 次复用：高并发、超时与资源回收验证

环境：Windows/amd64，Go 1.26.2，Intel Core i7-12700KF，本机真实 TLS/HTTP2 和 QUIC/HTTP3 服务。

## 测试配置

- `EnableConnectionReuse=true`，`MaxTotalRequests=256`。
- 单一目标地址，服务端最大并发流数设为 256。
- 1,024 个并发调用；日志确认实际峰值为 1,024。
- 每批 4,096 次请求，检查恰好创建 16 条连接，且每条连接恰好处理 256 次请求。
- 每种协议先预热一批，再执行三组“混合超时请求 + 正常恢复请求”。
- 混合批次使用 2 秒超时：3,584 次正常响应、256 次不返回响应头、256 次返回部分正文后停住。
- 每批完成后检查连接自动释放；批次间不调用清理函数，避免掩盖回收问题。

`MaxTotalRequests` 实际按共享 Transport 的获取次数计数。本测试使用单目标、无重定向，验证了它在该场景下对应每条连接 256 次请求；这不等于所有业务场景都按物理连接计数。

## 发现并修复的问题

HTTP3 正文读取在 deadline 到达时，可能只返回 `H3_REQUEST_CANCELLED (local)`。
取消按时生效，但调用方无法稳定通过 `errors.Is(err, context.DeadlineExceeded)`
或 `net.Error.Timeout()` 识别超时。fhttp 的旧式超时计时器与 request context
deadline 存在先后顺序差异，导致外层不一定将 QUIC 错误包装成超时错误。

`http3StreamBody.Read` 现在在释放自己的 context 前保留请求的取消原因，分别返回
`context.DeadlineExceeded` 或 `context.Canceled`；正常 EOF 保持不变。
精确回归测试先确认两种错误丢失，再验证修复后连续十轮竞态测试通过。

## 三轮竞态压力测试结果

命令：

```powershell
go test -race . -run '^TestReuse256' -count=3 -v -timeout=180s
```

三轮共 172,032 次请求、672 条连接，耗时 50.825 秒。
最终整包回归 `go test -race . ./tests/unit -count=1 -timeout=120s` 通过
（根包 22.314 秒），`go vet ./...`、全部包编译与 `git diff --check` 也通过。

| 项目 | HTTP2 | HTTP3 |
| --- | ---: | ---: |
| 请求总数 | 86,016 | 86,016 |
| 正常成功 | 81,408 | 81,408 |
| 预期响应头超时 | 2,304 | 2,304 |
| 预期响应体超时 | 2,304 | 2,304 |
| 非预期超时或请求失败 | 0 | 0 |
| 创建并回收的连接数 | 336 | 336 |
| 2 秒超时混合批次的最长请求耗时 | 2.011 秒 | 2.044 秒 |
| 正常批次 P99 范围（开启 race） | 62–91 毫秒 | 100–188 毫秒 |

每次超时批次之后的正常批次均通过，未出现共享连接被取消污染、请求串用、提前轮换截断其他流或持续卡住的情况。

## 资源回收

每批结束均断言：活动连接为 0、服务端活动处理器为 0、共享 Client 注册表条目为 0。
每种协议在预热后采样，再连续采样三组压力循环；最后检查 goroutine 和系统句柄。

| 资源 | HTTP2 | HTTP3 |
| --- | --- | --- |
| goroutine：基线 → 最终（三轮均一致） | 5 → 5 | 9 → 9 |
| Windows 进程句柄：基线 → 最终（三轮均一致） | 268 → 268 | 267 → 267 |
| 最终 GC 后存活堆内存（三轮范围） | 3.19–3.77 MiB | 3.77–3.80 MiB |
| GC 后内存趋势 | 最终均低于对应预热基线 | 最终均低于对应预热基线 |

测试未发现持续资源泄露。内存数字是 GC 后存活堆，不是进程工作集；运行时缓存、goroutine
栈和 race 检测器内存不会全部反映在该指标中。句柄按整个测试进程统计，并结合服务端观察
到的连接关闭做交叉验证。测试允许少量运行时线程句柄波动，实际三轮未出现增长。

这是有限时长的本机重复压力测试，未覆盖公网丢包、真实代理链路或数小时运行。依赖输出的
`reset err ... CANCEL` 来自人为制造的取消，判断结果以请求分类和资源断言为准。

复现文件：`reuse256_stress_test.go`、`reuse256_windows_test.go`。
`go test -short` 跳过这项较重的压力测试；Windows 之外仍检查连接、注册表和 goroutine，
不采集 Windows 进程句柄。
